Sinain · Save offer · wireframes
Sinain proposes, the user disposes. One click replaces five gestures.
When the user switches away after a long, engaged episode, a quiet offer appears: "Save these 47 min? IntelliJ, Chrome". Accept runs the exact save lifecycle that ships today (receipt → undo → commit); Adjust opens the existing chooser pre-filled; dismissal is one gesture or just waiting. Every response is a training label — the instrument that decides whether autosave ever ships. Zero LLM cost until accepted. Extends Deliberate Capture v2.dc.html — chooser, receipt, and card mode are reused untouched.
1 · The moment — a breakpoint, not an interruption
The offer fires only when the work-state engine detects a breakpoint — the user switches away from a thread they've been in for ≥ ~20 engaged minutes with real activity. The user's attention has already moved to a new context; the offer refers to the previous one. It must be glanceable-and-ignorable: silent arrival, never a modal, never over the new work.

C · The eye pulses save-green
Quietest, but mute. No evidence visible — the user must click to even learn what's offered, and a pulse can't say "47 min". Also overloads the eye's ambient language, which today means capture state, not requests. Kept as the fallback for hidden mode.

4 · Lifecycle — the card morphs into the receipt
One card for one save: accept and the offer morphs in place into the shipped receipt (Saving… → Saved · undo window → Committed) — the user never sees two cards. Adjust jumps to the standard chooser pre-filled. ✕ fades immediately; ignoring fades after ~45 s with no countdown bar (that idiom is reserved for undo).
