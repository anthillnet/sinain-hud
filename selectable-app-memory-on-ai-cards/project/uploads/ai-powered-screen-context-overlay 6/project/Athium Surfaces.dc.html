5 · The Calibrated Resume Card
Not a smart summary, and not "you seem distracted." Sinain predicts the cost and shape of returning to a thread, then shows the smallest reliable cue needed to resume — a calibrated re-entry instrument with a time band, a re-entry tier, and top-k next actions, each backed by visible evidence.
✓
The build rule. Show only claims that can be backed by visible evidence. Use predictions to choose timing and shape — not to impersonate certainty. So continuation_probability sets card loudness (never shown as a %), and wording softens to "likely / looks like / verify" when reliability is low.

6 · P1 — the attention cockpit (overlay UI)
The board becomes a Flutter surface in the overlay — an NSPanel sharingType .none, invisible to screen capture, so it's a private cockpit for the user's own glance. That forces it to be ambient and glanceable — not a dashboard.
!
Honesty rendering (binding). Unlike the /workstate inspector above (an eng/debug view, decimals fine), the cockpit shows qualitative tiers only — never raw scores. Need is order + a 3-tier glyph (⚠ now · ◷ soon · · later), warmth is color-cooled. Checkable evidence ("left with errors · 1d"), never affect ("you seem frustrated"). stuckness may color a card but carries no number and no "you're stuck" text.

7 · The resumption marker — how it distinguishes itself
The resume card rides the same region-eye → popover path as the issue markers — but it means something opposite. An issue eye says "I spotted a problem here." A resumption eye says "welcome back to a thread you left." Same mechanism, so it must read as a different kind at a glance — before anyone clicks.
↺
Form, not color, carries the meaning. The accent palette is user-customizable, so the resumption eye can't claim a second hue — it stays the same accent and same eye as every other marker. It distinguishes by a dashed “persisted” ring (recalled from storage, not live) and its tether, and by where it anchors: on the spot you left off, not on a freshly-flagged problem.
